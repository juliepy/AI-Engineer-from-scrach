# 2. 用例怎么写、怎么被发现

> **动手 Demo**：[demos/02-discovery](./demos/02-discovery/)  
> `cd demos/02-discovery && pytest -v` ；再试 `pytest -k login -v`

## 最小用例形态

```python
def test_login_ok():
    assert True

class TestUser:
    def test_create(self):
        assert 1 == 1
```

断言用 `assert` 即可，失败时 pytest 会打印左右值对比。

---

## 发现规则（默认识别谁是测试）

| 规则 | 例子 |
|------|------|
| 文件名 | `test_*.py` 或 `*_test.py` |
| 函数名 | `test_*` |
| 类名 | `Test*`（且类里不要有 `__init__`） |
| 方法名 | `test_*` |

不匹配命名 → **跑的时候根本不会执行**（CI 里「明明写了却没跑」常见坑）。

---

## 常用命令（背这几条）

```bash
pytest                      # 当前目录向下收集
pytest tests/smoke -v       # 只跑某目录
pytest tests/smoke/test_add.py::test_add   # 只跑一个函数
pytest -k login             # 名字里带 login 的
pytest -x                   # 遇到第一个失败就停（排障好用）
pytest --maxfail=3          # 失败 N 个后停
```

## fixture（了解即可）

用于准备/清理环境（临时目录、测试数据）。CI 面试说到「用例前置」时知道有这个概念：

```python
import pytest

@pytest.fixture
def client():
    return {"ok": True}

def test_api(client):
    assert client["ok"]
```

Day 1.5 不要求深挖 conftest；先保证会写断言 + 会按路径跑。

## 和门禁目录的对应（预习）

```
tests/
  smoke/      # MR
  gate1/      # Merge 后
  full/       # Daily
  release/    # 发版验收
```

每个目录下都是普通 `test_*.py`，**差别在「放哪 + 打什么标记」**，不是另一种测试语言。
