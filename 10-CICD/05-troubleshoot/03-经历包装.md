# 3. 经历包装（STAR 骨架）

把「维护 CI」说成可验证的故事，而不是「我写过 yml」。

## STAR 模板

| 段 | 写什么 |
|----|--------|
| **S** Situation | 哪条门禁 / 什么症状（MR 全红、Daily 超时、发版包找不到） |
| **T** Task | 你的职责：恢复门禁、缩短时长、保证可追溯 |
| **A** Action | 按五步排查做了什么；改了 rules / cache / 镜像 / 凭证哪一层 |
| **R** Result | 量化：时长从 X→Y；失败率；恢复耗时；是否避免关禁 |

---

## 示例故事 A：流水线不触发

- **S**：合入 main 后 Gate1 没跑，主干裸奔一天  
- **T**：当天恢复 Merge 后门禁  
- **A**：查 rules 发现只写了 MR 事件；补上 `main` + `push`；核对受保护分支  
- **R**：Gate1 恢复；补跑当日提交；加了「门禁 Job 必现」检查清单  

## 示例故事 B：测试 Job 变慢

- **S**：MR 反馈从 8 分钟涨到 25 分钟  
- **T**：压回 10 分钟内且不关用例  
- **A**：加 pip cache；smoke 与全量目录分离；Daily 吃全量  
- **R**：MR 回到 ~9 分钟；覆盖面转移到 Daily  

## 示例故事 C：凭证失效

- **S**：发版上传 Nexus 突然 401  
- **T**：恢复发版通道  
- **A**：核对 CI 变量与 Token 过期；轮换密钥；限制变量 mask  
- **R**：发版恢复；加到期提醒
