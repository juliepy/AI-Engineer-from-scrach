# 06 · 后台任务

场景：长编译放后台、SSH 断线任务死掉、本地保活调试、和 CI Job 的边界。

## 1. 三种层次（选对工具）

| 需求 | 做法 |
|------|------|
| 当前终端临时后台 | `cmd &` + `jobs` |
| 断线也继续 | `nohup` / `disown` / `screen`/`tmux` |
| 开机自启、崩溃拉起 | **systemd**（或 CI 调度，不要堆登录机） |

## 2. Job 控制

```bash
sleep 300 &
jobs -l
fg %1                 # 拉回前台
# Ctrl-Z 挂起 → bg %1 继续后台
kill %1
```

关闭终端时，未 `disown`/`nohup` 的后台进程常收 `SIGHUP` 退出。

## 3. nohup

```bash
nohup ./build.sh > build.log 2>&1 &
echo $!               # PID
tail -F build.log
```

`2>&1`：stderr 并进同一文件；只写 `>out` 会漏错误。

## 4. screen / tmux（可重连）

```bash
tmux new -s build
# 跑任务…
#  detach: Ctrl-b d
tmux attach -t build
tmux ls
```

适合「人肉守着的长任务」；正式环境仍应用 systemd/CI。

## 5. systemd 临时 / 常驻（了解）

```bash
# 一次性：
systemd-run --unit=manual-build --working-directory=/src ./build.sh
systemctl status manual-build
journalctl -u manual-build -f

# 常驻：写 /etc/systemd/system/foo.service → enable --now
```

## 6. 和 CI 的边界（面试常问）

- **CI Job**：生命周期绑在 Job；超时由 `timeout` / Runner 杀进程树。
- **登录机 nohup**：易遗漏、难审计、占资源 → 不推荐当「正式流水线」。
- 后台子进程泄漏：脚本里用 `wait`，或 `trap 'kill $(jobs -p)' EXIT`。
