# 02 · 网络调试

场景：拉依赖失败、Runner 注册不上、服务端口不通、DNS 错。

## 1. 分层排查（固定话术）

```
本机进程是否在听？ → ss / lsof
对端 IP 通不通？   → ping / traceroute（有的环境禁 ICMP）
端口通不通？       → nc -vz host port  或  curl
TLS/HTTP 对不对？  → curl -vI
DNS 是否正确？     → dig / getent hosts
防火墙 / 安全组？  → iptables/nft / 云控制台
```

## 2. 端口与连接

```bash
ss -lntp                     # LISTEN + 进程（需权限才显示 PID）
ss -antp | head
ss -s                        # 汇总
# 旧系统：
netstat -lntp
```

## 3. 连通性

```bash
ping -c 3 <host>
# 测 TCP 端口（有 nc）
nc -vz <host> 443
# 或 bash 内建：
timeout 3 bash -c 'echo >/dev/tcp/host/443' && echo open || echo closed

curl -vI --connect-timeout 5 https://example.com
curl -o /dev/null -s -w '%{http_code} time=%{time_total}\n' https://example.com
```

代理环境：检查 `http_proxy` / `HTTPS_PROXY` / `NO_PROXY`（CI 变量常踩坑）。

## 4. DNS

```bash
getent hosts gitlab.example.com
dig +short gitlab.example.com
resolvectl status            # systemd-resolved
cat /etc/resolv.conf
```

## 5. 路由与地址

```bash
ip addr
ip route
ip neigh | head
```

## 6. 抓包（了解即可）

```bash
sudo tcpdump -i any host <ip> and port 443 -nn -c 30 -w /tmp/a.pcap
# 再在本机 wireshark 打开，或：
tcpdump -r /tmp/a.pcap -nn
```

容器内抓包要进对 netns；K8s 常用 ephemeral debug 容器。

## 7. CI 高频故障对照

| 现象 | 先查 |
|------|------|
| `Could not resolve host` | DNS / `/etc/resolv.conf` / 公司内网 |
| `Connection timed out` | 路由、安全组、对端未听 |
| `Connection refused` | 对端进程没起来或端口错 |
| `SSL certificate problem` | 公司 MITM 证书未导入 |
| `Proxy CONNECT aborted` | 代理变量、白名单 |
