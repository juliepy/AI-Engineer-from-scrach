# 05 · 日志分析（系统层）

场景：服务挂了查系统日志；应用日志仍用 shell/python 模块深挖。

## 1. 三类日志

| 类型 | 位置 / 入口 | 典型命令 |
|------|-------------|----------|
| systemd 服务 | journal | `journalctl -u <unit>` |
| 传统 syslog | `/var/log/syslog`、`messages` | `tail` / `grep` |
| 内核 | ring buffer | `dmesg -T` |
| 应用 | 自定路径 / JSONL | → `01-basic-shell` / `02-log-python` |

## 2. journalctl 高频

```bash
journalctl -u gitlab-runner -n 200 --no-pager
journalctl -u docker -f                      # 跟随
journalctl --since "2026-08-04 09:00:00" --until "10:00"
journalctl -p err..alert -b                  # 本启动周期错误级
journalctl -k                                # 内核（类 dmesg）
```

## 3. 文本日志（与笔试题衔接）

```bash
tail -n 100 /var/log/syslog
tail -F /var/log/nginx/error.log
grep -E 'ERROR|FATAL|panic' /var/log/app/*.log | tail
# 时间窗（定长时间戳）：
awk '$0 >= "2026-08-01 09:00:00" && $0 <= "2026-08-01 12:00:00"' app.log
```

## 4. 磁盘与轮转

```bash
df -h
du -sh /var/log/* | sort -h | tail
journalctl --disk-usage
# 轮转配置常在 /etc/logrotate.d/
```

日志打满磁盘 → CI 莫名失败（写 artifacts、拉镜像都可能挂）。

## 5. 排查顺序

```
1. 应用自己的日志（Job log / app.log）
2. 相关 unit：journalctl -u …
3. 系统：syslog / dmesg（OOM、磁盘、网卡）
4. 容器：docker logs / kubectl logs
```

OOM 线索：

```bash
dmesg -T | grep -i oom
journalctl -k | grep -i oom
```
