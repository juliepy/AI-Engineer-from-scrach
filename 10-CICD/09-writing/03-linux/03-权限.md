# 03 · 权限

场景：`Permission denied`、脚本无法执行、CI 用户写不了目录、密钥权限过宽被拒绝。

## 1. 权限位怎么读

```
-rwxr-x---  1 alice ci  4096 Aug 4 10:00 run.sh
│└─┬─┘└┬┘└┬┘
│  u   g  o     u=属主 g=组 o=其他人
│
文件类型：- 文件  d 目录  l 软链
```

| 符号 | 八进制 | 含义 |
|------|--------|------|
| `r` | 4 | 读（目录=列目录） |
| `w` | 2 | 写（目录=增删入口） |
| `x` | 1 | 执行（目录=进入） |

目录要「进去」必须有 `x`；只给 `r` 不够。

## 2. 常用改法

```bash
chmod u+x script.sh
chmod 755 script.sh          # rwxr-xr-x
chmod 640 .env               # rw-r-----
chmod -R g+rX project/       # 大写 X：仅对目录/已可执行文件加 x
chown -R runner:runner workspace/
```

SSH 私钥过宽会被拒：

```bash
chmod 600 ~/.ssh/id_rsa
chmod 700 ~/.ssh
```

## 3. 身份与提权

```bash
whoami; id
sudo -l                      # 当前用户能 sudo 什么
sudo -u gitlab-runner -i
su - otheruser
```

CI 最佳实践：Job 用专用低权限用户；需要 root 的步骤进容器或明确 `sudo` 白名单。

## 4. 特殊位（了解）

| 位 | 含义 |
|----|------|
| `setuid`（`u+s`） | 以文件属主身份执行 |
| `setgid`（`g+s`） | 目录下新建文件继承组 |
| sticky（`+t`，如 `/tmp`） | 只能删自己的文件 |

## 5. ACL / 强制访问（遇到再查）

```bash
getfacl file
setfacl -m u:bob:rw file
# SELinux：
getenforce
ls -Z
```

## 6. 排查口诀

```
1. ls -l / stat 看属主与模式
2. 当前用户 id / groups 是否匹配
3. 路径上每一级目录是否有 x
4. 是否只读挂载（mount | grep ro）
5. 容器内用户与卷属主是否一致（常见 root 写出、runner 读不了）
```
